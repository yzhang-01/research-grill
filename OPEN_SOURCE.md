# Before the first public release

1. **Confirm release rights.** Research Grill uses the [MIT License](LICENSE) with the copyright notice `2026 yzhang-01`. Before publishing, confirm that the release is authorized and that the upstream notices and attribution are included. [Upstream notice](ACKNOWLEDGMENTS.md)
2. **Review the public tree and history.** Start from this release directory. Review every tracked path and the first commit. Keep local databases, real weekly reports, transcripts, private evidence links, account details, and mail credentials outside the repository. Use synthetic examples for documentation and bug reports.
3. **Verify fresh installs and existing reports.** Check the Codex discovery and end-to-end flow on Windows, macOS, and Linux. Cover English and Chinese, legacy imports, amended versions, and transfer into a separate workspace. Include one test with a person who has never used the skill. A standard-library language and compatibility regression test is included and can be run with `python -B -m unittest discover -s tests -v`.
4. **Document data boundaries.** Explain that a freeze and its timestamp are recorded on the user's device, and that a ZIP contains the participant's answers, assessments, and evidence index. Document how people can share records with teams or reviewers. Ask users to redact sensitive content before attaching packages to public issues.
5. **Create a small, versioned first release.** Agree on a project name and repository owner, publish the English and Chinese setup guides, add a synthetic example as a release asset if useful, and tag a first version after verification. Note that older installations need upgrading to import English reports. Define a contact or issue path for defects and compatibility problems.
