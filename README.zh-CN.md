# Research Grill 试用说明

[English](README.md)

Research Grill 是一个科研自我管理 Skill。自己定下这周要交付的成果，确认后锁定计划，再用每周自我答辩督促自己按计划推进。每次复盘会留下可回查的周报，便于个人归档和团队管理。

## 安装

1. 准备 Codex 和 Python 3.10 或更新版本，确保终端可运行 `python --version`。
2. 在 Codex 中打开本发行目录即可使用。要在其他项目中使用，请把完整的 `.agents/skills/research-grill/` 文件夹复制到对应项目的 `.agents/skills/` 下。
3. 用 Codex 打开该项目。在聊天输入框输入 `$`，搜索 `research-grill`。如果没显示，重新打开项目并新开一个聊天再搜索。

## 管理自己的科研计划

1. **设定目标。** 发送 `$research-grill 帮我设定本周目标。我计划读一篇论文，交付一条核心结论、原文位置和适用条件。先给我看草案。` 首次使用时确认项目标识、用户标识和显示名。课题组成员使用同一个项目标识，各自使用不同的用户标识。
2. **确认与记录。** 检查草案里的交付物、验收条件和截止日期，回复“确认冻结”。周中可发送 `$research-grill 记录本周进展和证据：……`。论文可提供页码和图表编号，代码可提供提交版本或 PR，实验可提供具体运行编号和日志链接。目标冻结后仍可追加进展或阻塞。
3. **答辩并导出。** 发送 `$research-grill 开始本周项目进度汇报`。每个目标至少有一轮针对性追问。没完成时，会追问尝试、阻塞和谁能帮忙。做完时，会追问具体产出和证据，也可以附文件请 Codex 查看内容。最后会问“你还有什么要补充的？”。回答完后，Codex 会返回 ZIP 路径，默认在项目的 `.research-grill/exports/`。
4. **归档周报。** 把 ZIP 保存到本地，或按团队协作需要分享。包中有可读周报、答辩原文和证据索引。分享时可以提供团队有权访问的原始材料链接，也可以另附原件。

如果想和正式记录分开，第一条可以加上“在当前项目下创建 `grill-demo` 子目录，并把它作为本次的记录工作区”。

可以用自己熟悉的语言对话。报告版式和固定末题支持英文和简体中文，答辩原话与记录正文保留原语言。导入英文包时，接收方需要使用这个版本。历史中文包仍可导入。

## 团队汇总

在装有同一 Skill 的项目里，把收到的 ZIP 放进工作区并发送：

> `$research-grill 导入这些周报包。按冻结的验收条件逐项核对，列出已完成、待补证和未完成的事项，并引用答辩原话或证据出处。`

汇总时可按成员、周次和版本回查记录。团队如需按固定节奏汇总，可以配置成员名单和汇总日期。

## 展望：把研究过程带进同行评审

我们建议期刊和会议在收稿时，将与稿件相关的 **Research Grill** 记录列为补充材料，并鼓励审稿人在需要核查时请作者提供对应记录。研究过程记录应覆盖关键阶段，说明作者提出了哪些假设、尝试了哪些方法、遇到了什么挫折，以及哪些结果促使他们调整方向。审稿人可以沿着这些记录，回查论文中的图表、数据和结论是怎样形成的。

一份优秀的研究记录应当如实保留试错、负结果和反复验证。最终图表呈现的是成果，过程记录还能让审稿人看到研究者在哪些环节投入了精力、做了哪些判断，以及如何回应意外结果。这些可核查的工作是评价研究投入的重要依据。

我们也建议把 AI 使用纳入同一套证据标准。作者可以说明 AI 参与了哪些环节，包括代码、分析、写作或制图，以及自己如何核验和修订产出。审稿时，重点应放在研究过程能否追溯、数据和结论能否核查，以及作者能否解释并承担关键研究判断。
